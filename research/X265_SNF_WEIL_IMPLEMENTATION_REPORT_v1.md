# X265 — production SNF/Weil implementation report v1

**Дата:** 27 ноября 2026 г.  
**Область:** только SNF/HNF решётки X265 и сертификат Weil/Miller.  
**Статус:** исполняемый exact-arithmetic candidate + независимые verifier-ы; Lean-перенос и внешний аудит ещё не выполнены.

## 0. Краткий итог

Подготовлены четыре исполняемых компонента:

1. `x265_snf_weil.py` — специализированный SNF для матриц
   \(M=[\mu_1\ \cdots\ \mu_s\mid NI_3]\), явные \(S,T,D\), точная проверка
   \(SMT=D\), контроль роста коэффициентов и Miller/Weil producer.
2. `x265_snf_weil_verify.py` — отдельный verifier без импорта producer-модуля;
   он независимо пересчитывает матричное равенство, определители, четыре Miller
   значения и pairing formula.
3. `x265_snf_weil_tests.py` — воспроизводимый тестовый набор.
4. `x265_snf_weil_test_results.json` — полный машинный протокол тестов.

**Важное разграничение:** это уже работающая exact-arithmetic реализация-кандидат,
но не готовый cryptographic production release и не Lean-доказательство. Python
не гарантирует constant-time поведение. Математическая оценка битовой сложности
для специальной прямоугольной обёртки выведена ниже; формальная проверка этой
оценки в Lean остаётся отдельной задачей.

## 1. Интерфейс SNF для матрицы X265

### 1.1 Входной контракт

На вход подаётся целочисленная матрица размера \(3\times(s+3)\):

\[
M=[\mu_1\ \cdots\ \mu_s\mid NI_3],\qquad
0\le (\mu_j)_i<N.
\]

Последние три столбца должны быть **в точности** \(NI_3\). Это не общий SNF
для произвольной матрицы \(3\times n\), а специализированный интерфейс X265.

### 1.2 Прямоугольная HNF-стадия

Рассмотрим \(A=M^T\). После перестановки строк три строки \(Ne_1,Ne_2,Ne_3\)
ставятся первыми. Первоначальный базис решётки:

\[
H_0=NI_3.
\]

После обработки первых \(j\) отношений поддерживается верхнетреугольная row-HNF
матрица \(H_j\), порождающая решётку, натянутую на \(NI_3\) и уже обработанные
\(\mu_1,\ldots,\mu_j\).

Для следующей строки \(v=\mu_{j+1}\) выполняется последовательное приведение
по диагональным pivot-ам:

\[
q_0=\lfloor v_0/h_{00}\rfloor,\quad v\leftarrow v-q_0H_0,
\]
\[
q_1=\lfloor v_1/h_{11}\rfloor,\quad v\leftarrow v-q_1H_1,
\]
\[
q_2=\lfloor v_2/h_{22}\rfloor,\quad v\leftarrow v-q_2H_2.
\]

В результате \(0\le v_i<h_{ii}\). Затем вычисляется row-HNF фиксированной матрицы
\(4\times3\), составленной из трёх строк \(H_j\) и строки \(v\). Возвращаемая
локальная матрица \(G_j\in GL_4(\mathbb Z)\) применяется одновременно к данным
и к накопленному преобразованию. Нижняя строка становится нулевой, первые три
строки образуют новый базис \(H_{j+1}\).

Поскольку решётка всегда содержит \(N\mathbb Z^3\), её HNF pivots делят \(N\),
а редуцированные наддиагональные элементы меньше соответствующих pivots.
Следовательно, все элементы \(H_j\) ограничены по модулю величиной \(N\).

После всех \(s\) вставок получаем явную unimodular-матрицу \(U\):

\[
UM^T=\begin{pmatrix}H_s\\0\end{pmatrix},
\qquad
MU^T=[H_s^T\mid0].
\]

### 1.3 Квадратная SNF-стадия

Остаётся привести невырожденную матрицу \(B=H_s^T\) размера \(3\times3\) к SNF.
Реализована Kannan–Bachem stabilization-схема:

1. очистить первый столбец row-gcd преобразованиями;
2. очистить первую строку column-gcd преобразованиями;
3. если pivot не делит некоторый элемент нижнего правого блока, ввести этот
   элемент в первую строку;
4. следующий gcd-pass заменяет pivot на его собственный делитель;
5. когда pivot делит весь нижний правый блок, рекурсивно обработать этот блок;
6. выполнить защитную gcd/lcm-нормализацию соседних диагональных элементов.

Все elementary row/column operations одновременно применяются к \(S\) и \(T\).

Если квадратная стадия даёт \(S_3BT_3=D_3\), то для исходной прямоугольной
матрицы берём

\[
S=S_3,\qquad T=U^T\operatorname{diag}(T_3,I_s),
\]

и получаем

\[
\boxed{SMT=[D_3\mid0].}
\]

Функция `verify_snf_certificate` проверяет равенство напрямую, а также
\(\det S,\det T\in\{\pm1\}\), положительность диагонали и цепочку делимости.
Независимый verifier реализует эти проверки отдельным кодом.

### 1.4 Извлечение базиса группы

Для X265 требуется

\[
(d_1,d_2,d_3)=(1,n_1,n_2),\qquad n_1n_2=N.
\]

Из \(S\) вычисляются столбцы \(S^{-1}e_j\). После применения отображения
\(\operatorname{ev}\) они дают кандидаты \(O,U,V\) порядков \(1,n_1,n_2\).
`snf_lattice_basis` проверяет \(d_1=1\) и \(d_1d_2d_3=N\), затем возвращает
все три коэффициентных вектора. Независимый group verifier дополнительно
проверяет точные порядки и Weil pairing.

## 2. Оценка роста коэффициентов для X265-обёртки

Пусть \(b=\lceil\log_2(N+1)\rceil\).

- Входные relation-строки приведены в диапазон \([0,N)^3\).
- Поддерживаемая HNF-матрица имеет элементы не больше \(N\).
- При приведении новой строки промежуточные частные имеют не более \(O(b)\)
  бит (грубая покоординатная оценка: \(q_0<N\), \(q_1<N^2\), \(q_2<N^3\)).
- Локальная HNF-матрица имеет фиксированный размер \(4\times3\): не более шести
  Bezout-блоков и трёх редукций над pivot-ами. Поэтому размер локальных
  коэффициентов ограничен \(C b\) битами для абсолютной константы \(C\), не
  зависящей от \(s,N\).
- Каждая вставка обновляет только четыре строки накопленного \(U\). Поэтому
  после \(s\) вставок размер коэффициентов \(U\) равен \(O(sb)\) битам.
- Квадратная стадия имеет фиксированный размер \(3\times3\); Kannan–Bachem
  SNF/HNF даёт полиномиальный битовый бюджет. Входные элементы \(B\) ограничены
  величиной \(N\), а \(|\det B|\le6N^3\).

Следовательно, при \(s=\lambda+9=\operatorname{polylog}N\) размер сертификата
и арифметический бюджет SNF остаются полилогарифмическими по \(N\). Это
специальная оценка для входа с блоком \(NI_3\), а не утверждение о произвольной
прямоугольной SNF-процедуре.

**Формальный статус:** доказательная схема роста коэффициентов зафиксирована,
но точные рекуррентные константы и соответствие исполняемого Python-кода
математическому псевдокоду ещё требуется оформить в Lean. Для квадратной
Kannan–Bachem стадии существует свежая Lean-формализация для невырожденных
квадратных матриц; она не формализует нашу прямоугольную X265-обёртку.

## 3. Miller / Weil pairing

### 3.1 Кривая и Miller step

Поддерживается короткая модель Вейерштрасса над простым полем:

\[
E:y^2=x^3+ax+b,\qquad p>3,\qquad4a^3+27b^2\ne0\pmod p.
\]

Для \(A,B,T\in E(\mathbb F_p)\), где \(T\ne O\), вычисляется

\[
g_{A,B}(T)=\frac{\ell_{A,B}(T)}{v_{A+B}(T)}.
\]

Особые случаи обработаны явно:

- если \(A=O\) или \(B=O\), значение равно 1;
- если \(A+B=O\), используется вертикальная функция \(x_T-x_A\);
- в остальных случаях используются секущая/касательная и вертикальная
  функция через \(A+B\).

Binary Miller loop вычисляет \(f_{n,P}(T)\), проверяя \(nP=O\) и завершаясь
только при ненулевом конечном значении.

### 3.2 Сдвинутая формула Weil

Используется именно ориентация X265 v1.1:

\[
\boxed{
 e_n(P,Q)=
 \frac{f_{n,P}(Q+S)}{f_{n,P}(S)}\cdot
 \frac{f_{n,Q}(-S)}{f_{n,Q}(P-S)}.
}
\]

Producer ищет вспомогательную точку \(S\), для которой все четыре Miller
аргумента конечны и все четыре значения ненулевые. `verify_weil_certificate`
пересчитывает четыре Miller значения отдельной реализацией, не вызывая
producer-функцию.

### 3.3 Точная равномерная выборка точки

Для \(x\in\mathbb F_p\) и знакового бита \(\epsilon\) используются токены
\(2x+\epsilon\), плюс один токен \(2p\), соответствующий \(O\). Для каждой
точки кривой существует ровно один принимаемый токен. Поэтому принятие
равномерного токена из \(\{0,\ldots,2p\}\) даёт точное равномерное распределение
на \(E(\mathbb F_p)\). Квадратные корни вычисляются Tonelli–Shanks; квадратичный
невычет ищется случайно и проверяется критерием Эйлера.

### 3.4 Число плохих вспомогательных точек

Один Miller chain содержит не более \(2\lfloor\log_2n\rfloor\) line/vertical
факторов. У каждого фактора носитель нулей/полюсов не более чем из пяти точек.
Для четырёх Miller evaluations объединение запрещённых сдвигов имеет размер
не более

\[
B_{\rm bad}\le40\lfloor\log_2n\rfloor.
\]

Если

\[
N=\#E(\mathbb F_p)>80\lfloor\log_2n\rfloor,
\]

то вероятность допустимого равномерного \(S\) строго больше \(1/2\), а число
равномерных точек-кандидатов до успеха имеет ожидание меньше двух. Сама
равномерная выборка точки использует ожидаемо \((2p+1)/N=2+o(1)\) токенов по
границе Хассе. Таким образом, поиск \(S\) имеет постоянную ожидаемую стоимость.

`max_aux_attempts=None` реализует неограниченный Las Vegas поиск; конечный cap
возвращает ошибку и должен трактоваться вызывающим алгоритмом как
`RETRY_ATTEMPT`, а не как отрицательный сертификат.

### 3.5 Проверка базиса группы

Для \(n_1\mid n_2\), \(n_1n_2=N\), проверяются точные порядки \(U,V\), затем
\(W=(n_2/n_1)V\) и примитивность \(e_{n_1}(U,W)\):

\[
\eta^{n_1}=1,\qquad
\eta^{n_1/\ell}\ne1\quad\text{для каждого простого }\ell\mid n_1.
\]

Это исключает зависимость \(U,V\) и доказывает, что они порождают группу
порядка \(N\). Циклический случай \(n_1=1\) обрабатывается отдельно.

Для простоты \(p<2^{64}\) применяется детерминированный Miller–Rabin с
известным набором оснований; для больших простых поддерживается проверка
Pocklington-сертификата. Полная факторизация \(N\), доказательства простоты
факторов и точный подсчёт \(\#E(\mathbb F_p)\) остаются входными сертификатами
предыдущих этапов X265.

## 4. Независимая проверка

`x265_snf_weil_verify.py` не импортирует producer-модуль. Он самостоятельно
реализует:

- умножение целочисленных матриц и Bareiss determinant;
- проверку \(SMT=D\), \(\det S=\pm1\), \(\det T=\pm1\);
- group law на короткой кривой;
- Miller recurrence и shifted-divisor pairing;
- проверку точных порядков и примитивности pairing в group-basis certificate.

Это независимый программный путь, но не независимая человеческая экспертиза и
не формальная верификация. Обе программы всё ещё используют одну и ту же
математическую формулу Weil pairing.

## 5. Тесты

Воспроизводимый seed: `20261127`.

- 1 000 случайных X265-матриц \(3\times(s+3)\): SNF-инварианты совпали с
  SymPy; оба verifier-а подтвердили сертификаты.
- 2 000 случайных квадратных \(3\times3\) SNF: совпадение с SymPy.
- Размеры входных коэффициентов 64, 128, 256, 512, 1024 и 2048 бит; до 80
  столбцов. Дополнительно проверены структурированные решётки с инвариантами
  \((1,n_1,n_2)\) и \(n_1n_2=N\).
- 10 малых эллиптических кривых с различными структурами группы; 10 тестов
  извлечения базиса из SNF-ядра.
- 9 нециклических случаев: alternating, antisymmetry и bilinearity pairing.
- Негативные тесты: изменение \(S,T,D\), Miller values, \(\eta\) и списка
  простых делителей отвергается verifier-ом.
- 65-битное простое поле с Pocklington-сертификатом; на кривой
  \(y^2=x^3-x\) проверено \(e_2((0,0),(1,0))=-1\pmod p\) независимым verifier-ом.

SymPy используется только как тестовый oracle и не является runtime-зависимостью
двух implementation-модулей.

## 6. Оставшиеся блокеры

1. **Lean:** нет единой сборки, которая доказывает точную корректность данного
   rectangular wrapper и Miller/Weil verifier-а. Свежая Lean-работа по
   Kannan–Bachem SNF охватывает невырожденные квадратные целочисленные матрицы,
   а не наш прямоугольный вход.
2. **Внешняя экспертиза:** не проводилась.
3. **Production crypto hardening:** Python bigint/modular inverse не constant-time;
   для реального криптографического deployment нужен constant-time backend.
4. **Upstream certificates:** факторизация \(N\), primality certificates для
   всех больших факторов, точный group order и Count15 witness должны приходить
   из соответствующих проверенных X263/X264/Count15 модулей.
5. **End-to-end complexity:** данный модуль не включает Count15, сбор отношений,
   поиск дилатаций, CRT и полный ECDLP pipeline. Он закрывает только SNF/Weil
   интерфейсную часть.

Поэтому ограничение №3 из списка пользователя теперь имеет исполняемую exact-
arithmetic реализацию-кандидат и явный битовый анализ, но до единой Lean-сборки
и внешнего аудита его нельзя отмечать полностью закрытым.
